# ADR-0022: Retire completed authoring tools and unused ORM

Status: Accepted under owner-authorized behavior-preserving cleanup
Date: 2026-10-01
Decision owner: Christopher Guzowski

## Context

The owner requested a thorough demo cleanup, explicitly including completed
Python PDF-generation tooling while preserving useful historical records.
None of the 13 authoring scripts are invoked by application startup, build or CI.
Frozen metadata pins some of their hashes; deleting the bytes outright would
lose historical reproduction capability.

All API repositories use JdbcClient. There are no JPA entities, repositories,
EntityManager usages or ORM-owned data mappings. The JPA starter provides JDBC
transitively but also packages and initializes an unused persistence stack.

## Decision

Retire all Python authoring source files into one historical ZIP under SynTen Inc,
preserving exact original paths/bytes and per-file/archive hashes with restoration
instructions. Keep frozen sources, PDFs, manifests and control records unchanged.
Original authoring commands apply after restoring the archive in a reproduction
checkout. Active PDF integrity/readiness/parsing remains Java-owned and unchanged.

Replace the unused JPA starter with the already-used JDBC starter. Remove dormant
Hibernate configuration. Preserve Hikari, JdbcClient, Spring transactions, Flyway,
UTC application timestamps, PostgreSQL and all schema migrations. No application
schema is generated by an ORM. Do not remove Hibernate Validator: HTTP validation
uses it independently of Hibernate ORM.

Keep CI/tests, startup/preparation commands, independently runnable MCP service,
and offline evaluators: they verify and reproduce supported functionality/results.
Do not prune public commands merely because they are unused in an ordinary demo.

## Consequences and verification

Historical PDF rebuilding becomes an explicit archive-restoration operation.
Application behavior and persisted data remain unchanged. Existing rollback
characterization tests must pass before/after the transaction-manager change;
the full gate must cover persistence, concurrency, failure paths and all workflows.
Archive restoration/hashes and frozen inputs must be verified independently.
Revisit only if an actual JPA mapping or new authoring task is authorized.
